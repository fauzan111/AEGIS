Gate 1 · Technologies, Planning & Feasibility

The technology approach, the schedule, and why it's feasible

Gate 1 established the case for AEGIS: what technologies it needed, how the project would be scheduled, whether it was technically feasible, and what the economic case for it looks like.

1.1 Technologies

What AEGIS is built on

5G control-plane surface

The 5G Service-Based Architecture and Service-Based Interface: Network Functions (AMF, SMF, NRF, PCF, UDM, NEF) exposing HTTP/2 REST APIs.

Zero-Trust security

NIST SP 800-207: continuous, per-request verification of machine identities, applied to behaviour rather than credentials alone.

Behavioural ML

Unsupervised anomaly detection (Isolation Forest) trained only on legitimate traffic, combined with deterministic policy rules and a session-state machine.

Detection features

Request rate and timing, distinct Network Functions and endpoints, method mix, call-sequence integrity, error rate, payload size, time of day.

Data & tooling

A synthetic 5G SBA traffic generator, scikit-learn and pandas for modelling, a Streamlit dashboard for the PASS / STEP-UP / BLOCK gate.

Standards

NIST SP 800-207, 3GPP SBA, TM Forum closed-loop automation, aligned with NIS2, GDPR, and the EU AI Act.

1.3 Feasibility Analysis

De-risked by a working baseline, not just a plan

Resources are entirely open-source and run on a standard laptop. The main external risk, access to real network traffic, is mitigated by a synthetic-first approach: a working baseline already demonstrated detection across all seven modelled threat classes before Gate 2 hardened and rigorously evaluated it.

RiskMitigation
Synthetic data may not capture real agent behaviourModelled on 3GPP SBA semantics; the pipeline ingests real logs when available
False positives disrupt operationsHeld-out calibration plus a soft STEP-UP action before BLOCK; thresholds are tunable
Real-data access is not grantedThe full PoC is deliverable on synthetic data alone
Adaptive or evasive attackersLayered rules, ML, and a session-state machine; roadmap for periodic retraining
1.4 Economic / Business Analysis

Why this is worth building

Cost

Development is engineering time only, open-source, no licensing. Production adds modest edge compute for the inline gate.

Risk avoided

Catching a compromised or spoofed automation before it acts cuts mean-time-to-detect from hours to seconds.

Enabler of automation

Zero-trust on machine identities is the guardrail that lets an operator safely expand network automation.

Compliance & audit

Supports a NIS2 zero-trust posture; explainable, logged decisions provide audit evidence for GDPR and the EU AI Act.

Operational efficiency

Automates machine-identity monitoring that cannot be performed manually at API scale.

Market relevance

Securing AI agents on critical infrastructure is an emerging priority; AEGIS covers a gap credential-based AAA doesn't.

The Working Prototype

See it decide, in real time

Every request window from a machine agent is scored against that agent's own behavioural fingerprint, then gated: PASS, STEP-UP, or BLOCK, always with a plain-language reason.

The Problem

Authentication proves what you have. Not who you are.

Orchestration tools, closed-loop automation, and AI copilots now call 5G Network Functions directly. A stolen token or compromised automation still passes normal authentication, the credential is valid, but the actor behind it isn't. AEGIS answers the question authentication never asks: is this really our agent, behaving the way it always does?

In scope

Service and automation agents calling 5G control-plane APIs (the Service-Based Interface).

Out of scope

End-user devices, the data plane / user traffic, and general AI safety.

Standard

Built on NIST SP 800-207 zero-trust principles: never trust, always verify, verify continuously.

How It Works

Observe → Fingerprint → Score → Decide

01

Observe

Log every request: agent, target system, timing, size, status.

02

Fingerprint

Compare the last 60s of activity to that agent's own known-good baseline.

03

Score

Deterministic rules + an Isolation Forest (trained on legitimate traffic only) combine into one risk value.

04

Decide

Fixed thresholds turn the risk score into a gate decision, automatically.

PASSBehaves like its known-good self
STEP-UPChallenge: re-authenticate, approve, or throttle
BLOCKQuarantine the identity, alert the SOC

Threat Model

Seven attacks, all built and detected

We assume the attacker already holds a valid credential, the realistic, hard case, and catch them by behaviour instead.

IDThreatWhat it looks like
T1ImpersonationValid token, behaves like a different agent
T2Compromised agentA legitimate agent drifts into new behaviour
T3ReconnaissanceBroad scanning across systems, high error rate
T4Volumetric abuseRequest-rate spike far above normal
T5Slow exfiltrationQuiet, large data pulls, off-hours
T6Broken sequenceCloses a session that was never opened
T7Scope creepTouches systems outside its onboarded role
Results

Proof it works, benchmarked against real detection systems

Measured on about 11,365 request windows the model never saw during training, drawn from 210,000 simulated 5G control-plane requests across 5 agents and all 7 injected attack types. Thresholds are tuned for a realistic false-positive budget, not the highest possible numbers, so detection is intentionally uneven across threats: 100 percent for loud, unambiguous signals like volumetric spikes and scope-policy violations, and 76 to 96 percent for statistically subtle threats like slow reconnaissance and exfiltration, matching published network intrusion detection and industry SOC benchmarks.
